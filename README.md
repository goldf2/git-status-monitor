# GitFinder

面向本地开发工作的桌面工作台，逐步统一目录文件、Git、文档、终端与项目任务入口。Electron 桌面应用是主要产品，CLI 和仅本机 Web 页面用于辅助检查。

长期边界与当前差距见 [CONTEXT.md](CONTEXT.md)、[产品差距分析](docs/PRODUCT_GAP_ANALYSIS.md) 和 [开发工作台 ADR](docs/adr/0001-development-workspace-shell.md)。v1.30.11 的受限 ZIP Quick Look 与真实安装版验收见 [v1.30.11 验收记录](docs/v1.30.11-验收记录.md)；v1.30.9 的关系白板视觉分组见 [v1.30.9 验收记录](docs/v1.30.9-验收记录.md)。v1.26.0 的项目身份、文件冲突与 Windows x64 交付链见 [v1.26.0 验收记录](docs/v1.26.0-验收记录.md)、[本地项目身份 ADR](docs/adr/0007-local-project-identity.md) 和 [Windows 发布 ADR](docs/adr/0008-windows-release-gate.md)。

## 功能特性

- 📁 **仓库扫描** - 递归扫描指定目录下的所有 Git 仓库
- 📊 **状态监控** - 受控并发读取大量仓库的本地 Git 状态，显示进度并可取消；默认不隐式 fetch
- 📈 **统计面板** - 可视化展示已同步/未提交/未推送/需拉取数量
- 🔧 **Git 审查** - 支持文件级 diff、暂存/取消暂存、明确提交范围，以及 pull、push、fetch
- 🌐 **远程管理** - 添加、修改远程仓库地址
- 📋 **变更详情** - 查看文件变更列表和差异统计
- 🎨 **四种目录视图** - 图标、列表、Finder 式分栏与图库可使用全局默认，也可让每个目录分别记住视图、排序与分栏宽度；海量目录逐帧补齐，超大列表只渲染视口附近行
- 📄 **文件与目录** - 目录模式统一展示普通文件、文件夹和 Git 属性；项目身份、可配置颜色与 Git 角标相互独立
- 🗂️ **本地项目** - 用户显式“设为项目”后创建便携的 `.gitfinder/project.json`；项目可聚合零个、一个或多个仓库，嵌套项目自成边界
- ↔️ **安全整理** - 支持新建、剪切/复制/粘贴、制作副本、Finder 式批量重命名、批量移动、拖放和系统废纸篓/回收站；冲突可批量选择保留两者、替换或跳过
- 🕘 **文件操作历史** - 从“操作”下拉或系统“显示”菜单检查最近文件动作、撤销状态和恢复结果，并在 GitFinder 内返回操作位置
- ℹ️ **显示简介** - 单选后通过“操作”、右键、macOS `⌘I` 或 Windows `Alt+Enter` 打开非模态检查器，查看类型、路径、大小、日期、权限、项目身份与 Git 属性
- 📥 **外部导入** - 从 Finder 或桌面拖入后先预览复制计划；同名内容自动保留两份，确认前零写入，导入后可撤销
- 👁️ **Quick Look** - 空格安全预览文本、Markdown、JSON、YAML、TOML、plist、日志、代码、栅格图片、ZIP 目录和文件夹摘要；ZIP 只读列出受限中央目录，不解压或读取条目正文，macOS 二进制 plist 仅在用户明确点击后调用系统 `plutil` 生成内存只读预览，大型开发文本可按需加载后续分段
- 🗂️ **工作区标签页** - 每个标签独立保存路径、导航历史、视图与搜索状态，支持拖拽重排和关闭后恢复；标签溢出时提供左右浏览按钮，并用强调色指出屏幕外活动标签的方向
- 🧭 **Finder 风格导航** - 后退、前进、上级目录和安全“前往文件夹”组成固定导航组，明确提示目标位置；受管根之外的祖先只作为位置上下文，不能通过面包屑、历史或快捷键越界；视图、新建、文件操作、类型与排列收进可访问下拉菜单
- 📍 **受管位置树** - 左侧“位置”只列出用户明确添加的受管根及其目录层级，不把整台机器的磁盘伪装成可浏览位置；根节点保留项目颜色与 Git 角标，断开位置可见但不会触发无效读取
- 🗂️ **Finder 式连续浏览** - 图标、列表、分栏和图库可用 `⌘1/2/3/4`（Windows 为 `Ctrl+1/2/3/4`）切换；分栏连续展示祖先目录并支持拖动、键盘调整和记忆列宽，图库以大预览和带图片缩略图的胶片条浏览图片、Markdown、开发文本与目录摘要
- ⭐ **侧栏收藏夹** - 普通文件夹、项目文件夹和 Git 仓库均可从操作菜单、右键菜单或详情加入收藏；项目颜色与 Git 角标保持叠加显示，重命名或移动后自动重绑定
- 📌 **项目快捷入口** - 左侧“项目”只展示所有项目入口、用户固定项目和最近项目；点击具体项目进入统一目录页，不恢复项目分类或独立项目视图，并可在应用设置中隐藏项目区、隐藏最近项目或限制最近数量
- ⌨️ **平台快捷键** - macOS 使用 Finder 习惯的 ⌘/Return/⌘⌫，并用 `⌥⌘C` 复制路径名；Windows 使用 Ctrl+C/X/V/A、F2、Delete 和 `Ctrl+Shift+C` 复制路径名
- 🧰 **开发工具** - 从操作菜单、右键或系统“文件”菜单在首选终端中打开当前目录、选中文件夹或文件所在目录；同时发现 Windows Terminal、PowerShell、Git for Windows、VS Code 与 PyCharm，缺失时可在设置中手动选择程序
- 🔍 **全局搜索** - 名称/路径模式复用仅含文件系统元数据的持久化增量索引，仓库即时叠加分类和标签；显式切换“文件内容”后可执行受限、可取消且不落盘的本机文本搜索
- ✓ **开发任务** - 接入 Local Project Manager schema 1.1，以列表、状态看板、持久化时间线、里程碑或只读“依赖验收”视图查看任务、前后置关系、验收门禁、测试和自动化事实；创建、推进或编辑继续经过差异预览与人工确认
- ◇ **关系白板** - 用项目→仓库→部署→服务器事实链表达本机开发与部署关系；部署节点独立保存环境、版本、分支、提交和声明状态，服务器详情直接聚合关联项目、仓库与部署版本并可回到白板节点；拖动布局或查看摘要不会执行部署或 Git 写操作
- ⏱️ **自动刷新** - 当前打开目录由受管文件系统监听自动吸收外部新建、重命名和移走；Git 状态仍支持定时刷新
- 🔌 **断开恢复** - 外接磁盘或网络受管根暂时不可用时保留原标签页与路径，重连后可原地重试，不把一次断线误判成目录删除
- 🚫 **排除仓库** - 暂时隐藏不想监控的仓库

## 使用方式

### 1. CLI 命令行

```bash
# 扫描仓库（默认路径 /Volumes/project，深度 2）
npm run scan

# 指定路径和深度
node cli.js scan --path /Users/user/projects --depth 3

# 查看缓存状态（快速）
npm run status

# 启动 Web 服务器
node cli.js server

# 清除缓存
node cli.js clear

# 查看帮助
node cli.js --help
```

### 2. Web 服务器

```bash
npm start
# 访问 http://localhost:3001
```

Web 服务只监听 `127.0.0.1`，且 pull、push、fetch、commit 和远程地址修改默认关闭。仅在可信本机环境确有需要时，以 `GITFINDER_WEB_WRITE_ENABLED=1 npm start` 显式启用；桌面应用不受该开关影响。

### 3. Electron 桌面应用

```bash
npm run electron
```

文件操作只允许发生在用户已添加的受管开发目录内，不能直接移动或删除受管根目录。删除默认进入系统废纸篓，复制会自动生成不覆盖原文件的“副本”名称，移动和重命名会同步仓库注册表、分类、收藏与标签页路径；单项重命名刷新后继续选中新路径并恢复键盘焦点，普通文件默认只选中最后一个扩展名前的基本名称，文件夹仍选中完整名称。最近 200 次文件操作保存在本机，可撤销的操作会在工具栏中提供入口。新建文件使用独占创建，不覆盖同名内容；只有文件仍为空且没有被替换时才允许撤销。通过符号链接离开受管根目录的写入会被拒绝。用于文件复制/剪切/粘贴的应用内剪贴板只在本次 GitFinder 会话中生效，不读取或覆盖系统文件剪贴板；“复制为路径名”则会将经过主进程受管路径复核的绝对路径文本写入系统剪贴板，多选时每行一个，方便粘贴到终端、编辑器、文档或消息中，不改变应用内文件剪贴板。

在 GitFinder 内拖动文件或文件夹时默认预览移动；macOS 按住 `⌥ Option`、Windows/Linux 按住 `Ctrl` 会即时切换为复制。系统光标、目标轮廓和顶部状态提示会随修饰键连续更新，释放后仍只打开既有的零写入传输预览，不会直接改动文件。同目录拖拽复制会按 Finder 式副本命名；移动到原目录、拖到自身或自身内部始终拒绝。复制与移动最终都由主进程重新检查受管路径、冲突、结构风险和跨卷语义。

“操作 → 文件操作历史…”和系统“显示 → 文件操作历史”打开同一个非模态检查面板。面板展示最近 50 条记录的动作、项目数、时间、撤销/重做失效、Windows 回收站恢复边界以及中断恢复结果；只为当前合法候选显示撤销或重做按钮。定位操作会回到 GitFinder 的受管目录并选择仍存在的项目，不会唤起 Finder，也不会把系统废纸篓内部路径当成工作位置。历史面板只读取现有本机操作日志，不创建第二份文件事实，也不增加新的文件写入能力。

单选文件或文件夹后，“操作 → 显示简介”、右键“显示简介”、macOS `⌘I` 与 Windows `Alt+Enter` 打开同一个非模态右侧检查器。它显示类型、完整路径、文件大小、修改/创建/访问时间、读写执行权限、隐藏/链接属性，并将“本地项目”和“Git 仓库”作为可叠加维度展示。文件夹体积在主进程后台异步扫描，包含隐藏内容与依赖目录，持续显示已扫描项目数，并可随时停止；扫描不会跟随符号链接进入其他目录，无法读取的项目会在摘要中明确列出。默认应用打开和系统文件管理器定位只是可选互操作入口，执行前仍重新校验受管真实路径，面板本身不写文件也不执行 Git 操作。

“在终端中打开”复用应用设置中的首选终端：没有选择时打开当前真实目录，单选文件夹时打开该文件夹，单选文件时打开其父目录；多选、全局搜索无选择或受管范围外目标不会猜测工作目录。工具栏“操作”、文件右键菜单和系统“文件”菜单共用同一入口，主进程会重新解析真实受管路径和目标类型。该入口只启动外部终端并传入工作目录，不执行 shell 命令，也不自动修改 Git 状态；终端不可用时会引导到开发工具设置。

应用“编辑”菜单与目录快捷键共用同一套文件动作路由：在文件浏览区使用撤销、重做、剪切、复制、粘贴和全选时操作目录项目；输入框、编辑器或主动选中的文字仍交给系统原生文本编辑。工具栏“操作”、右键菜单、应用“编辑”菜单及 macOS `⌥⌘C` / Windows `Ctrl+Shift+C` 都可将所选绝对路径复制为系统剪贴板文本。Quick Look 和阻塞弹窗打开时不会误操作背后的文件。重做只接受刚由 GitFinder 撤销、文件身份仍匹配且原目标未被占用的操作；新文件操作会废弃旧重做链，失败不覆盖现有内容。新建文件/文件夹、同卷移动与重命名、废纸篓、复制及导入可安全重做；跨卷移动撤销后需重新发起传输检查，不绕过复制校验门禁。

多选 2–200 个文件或文件夹后，工具栏“操作”、右键菜单以及 macOS `Return` / Windows `F2` 会打开同一个批量重命名窗口。可按字面替换文本、在名称前后添加文本，或使用保留扩展名的连续序号格式化名称；列表即时展示旧名称到新名称，确认前零写入。主进程会复核来源身份、重复名称和现有目标，项目根、`.gitfinder`、`.git` 或内部仓库需要显式风险确认。执行采用同目录两阶段重命名，可安全处理名称互换和仅大小写变化；任一步骤、配置重绑定或历史写入失败都会回滚完整批次。异常退出时恢复日志只处理明确记录的隐藏暂存路径，完整提交会补齐配置与撤销记录，部分提交则回滚或保留现场要求检查。成功操作可整体撤销和重做，不会自动暂存、提交或推送 Git。

受管根目录只能从系统文件夹选择器加入；选择结果携带与精确目录绑定、短时有效且只能消费一次的授权，渲染页面不能凭任意路径静默扩大受管范围。目录读取、仓库扫描、简介、README、默认应用打开、系统定位、标签检测和目录体积等旧文件系统 IPC 会统一复核真实受管路径、目标类型与符号链接边界。应用设置只允许写入明确列出的本机偏好，不能替换受管根或收藏。项目 Markdown、CSV 和 `AGENTS.md` 的读写会重新校验真实路径，并拒绝符号链接、硬链接、越界位置和超限内容。

内嵌终端只接受真实受管目录作为工作目录。每条命令都会在主进程弹出原生系统确认，完整显示工作目录和命令，默认操作是取消；取消返回退出码 130。确认执行后命令仍由系统 shell 运行，并不构成容器或沙箱，因此已确认的命令仍可能修改项目或访问其他本机位置。

目录模式只监听当前可见且位于受管根内的目录，不递归监视整棵项目树。来自终端、编辑器、Finder 或其他程序的新建、重命名和移走会在短时间内合并刷新，同时保留仍存在的选择项并使文件索引和 Git 状态缓存失效。若受管根仍在线但当前子目录确实被移走或删除，标签页按既有历史/祖先规则回退到可用位置并清除失效选择；若整个外接磁盘或网络受管根暂时不可用，则保留原标签页、历史和路径，在当前内容区显示“重试连接／选择其他位置”，重连后原地恢复。GitFinder 不自动挂载磁盘、不高频轮询，也不会因为一次断线删除、移动或修改文件。

macOS 上的删除目标按来源卷选择：系统卷使用用户的 `~/.Trash`，外接卷使用该卷的 `.Trashes/<uid>`。GitFinder 会验证废纸篓是真实目录且与来源位于同一设备；不满足条件时零写入拒绝，不回退到跨卷复制删除。因此外接盘的大目录删除和相应撤销通常只是同卷原子重命名。

Windows 上的删除使用 Electron 的系统 Recycle Bin 能力，不在用户目录伪造 `.Trash`。由于系统回收站不返回可靠的恢复目标路径，GitFinder 不伪造“可撤销”历史；如需恢复，用户在 Windows 回收站中操作。Windows 名称校验拒绝保留名、尾部点/空格和非法字符；符号链接权限不足时会明确提示开发者模式或权限要求。

复制、移动、粘贴和外部导入会先递归统计项目、识别来源/目标卷并检查目标卷可用空间，确认前零写入。同卷移动使用原子重命名；复制和跨卷移动先写入隐藏临时项，对每个普通文件执行 SHA-256 字节校验，再以独占方式提交最终目标。准备阶段可安全取消且不删除来源；跨卷移动只在所有目标提交后删除来源。应用异常退出后只自动清理恢复记录明确指向的隐藏临时项；若文件已全部提交但历史未落盘，会补齐路径关联和可撤销记录；部分提交、来源和目标同时存在、临时项可能是唯一副本等歧义情况会保留原样并要求人工检查。

同名冲突默认“保留两者”，也可对整批选择“替换”或“跳过”。替换会先在同一目录中隐藏备份旧目标，新内容完成校验与提交后才清理备份；任何提交失败会恢复旧目标。替换操作不伪造可撤销。移动项目根、`.gitfinder`、`.git` 或嵌套仓库时，预览会列出风险并要求显式勾选，主进程仍会二次校验。

移动、重命名、废纸篓和撤销可能同时更新仓库注册表、扫描清单和桌面偏好。这些路径关联使用本机预写日志作为一个配置事务：正常写入使用 `0600` 权限的原子替换并同步到磁盘，中途失败时整体回滚，异常退出后启动时完成向前恢复或待定回滚。损坏、超限或不安全的事务记录会原样保留，并暂停后续路径修改，避免在不确定状态下继续扩大影响。

从 Finder 或桌面拖入文件/文件夹时，GitFinder 只把它视为“复制导入”，不会移动或修改来源。释放后先显示目标、项目清单、大小和同名冲突；确认前不创建操作历史或目标文件。同名内容使用 Finder 式“副本”名称，确认时会重新校验来源和目标，任何预览后变化都会拒绝写入；一次最多导入 100 个顶层项目，导入结果可用 `⌘Z` 移到废纸篓。拖入目标只限受管目录、其中的文件夹、侧栏位置或已打开标签页。

窗口较窄或左右面板较宽时，应用会为中央文件区保留可用宽度；顶部视图入口自动收紧为图标，文件操作与排列选项通过弹出菜单分组，不再依赖长排按钮或横向滚动，避免中文文字被压成竖排或互相覆盖。

标签页通过 `⌘T` 新建、`⌘W` 关闭、`⌘⇧T` 恢复最近关闭项，并可用 `Control+Tab` 切换。可直接拖动标签调整顺序；拖到可见区域边缘时会连续滚动，顺序在释放后立即保存。键盘用户聚焦标签后可用 `⌥⇧←/→` 左右移动。标签总宽度超过窗口时，标签栏显示左右浏览按钮；活动标签被横向滚动到屏幕外后，对应方向按钮会使用强调色提示，点击时优先直接找回活动标签，活动标签已可见时则按约 72% 可见宽度继续浏览。每次切换、恢复或重排也会重新保证活动标签可见。悬停提示只显示完整标签名称，不再用绝对路径形成遮挡工具栏的大块原生提示；路径仍保留在无障碍名称中。每个标签独立保存目录、前进/后退历史、视图模式、搜索条件和“全部／文件夹／Git 仓库／文件”类型筛选，重排、关闭或重新启动应用后状态保持不变。启动时会在受管根目录边界内校验所有打开和最近关闭标签：受管根在线而当前位置失效时，优先回退到最近仍存在的历史位置，再尝试最近可用祖先和首个可用受管根；整个受管根断开时则保留路径等待重连。符号链接不能借此逃逸受管根。

工具栏文件夹箭头、应用“前往”菜单或 macOS `⌘⇧G` / Windows `Ctrl+L` 可打开“前往文件夹”。弹窗提供当前路径、标签页历史和受管位置建议，接受绝对路径、成对引号及 `~`；路径由主进程按真实受管根二次解析。相对路径、普通文件、缺失目录、受管根外位置和符号链接越界均保持零导航并显示明确原因；它不会因为输入路径而自动扩大受管范围。

左侧“位置”直接以用户通过系统选择器添加的目录作为树根。项目根使用配置的项目颜色，Git 根继续叠加紫色角标；根的折叠状态跨重启保存，子目录展开仅保留在当前会话。暂时断开的根保留名称和路径但禁用浏览，后台仓库扫描跳过它并保留原仓库索引及原扫描时间；受管根本身是 Git 仓库时也会进入全部仓库与仪表盘结果。

侧栏收藏夹表达“文件夹位置”，不再借用仓库标签。新收藏只能来自用户已添加的受管位置，并由主进程校验真实目录、符号链接边界和数量上限；既有版本保存的合法目录收藏继续兼容。目录卡片、列表项和仓库详情都使用同一收藏状态，重命名、移动、归档或恢复时由路径配置事务同步更新。Git 只是文件夹上的角标，项目身份和项目颜色仍独立保留。

项目和 Git 仓库不再作为一级视图，固定的“项目/仓库分类”也不再占用侧栏。左侧“项目”只是导航快捷区：显示所有项目、用户固定项目和最多 8 个最近项目；点击具体项目进入同一目录页，“所有项目”应用所有受管位置的项目筛选。快捷偏好只保存稳定 `projectId`、最近时间和最后已知名称，不写绝对路径或 `.gitfinder/project.json`；项目移动后按稳定身份重新解析，暂时失效的固定项目可见且可取消固定。仓库分类迁入全部仓库与仪表盘的筛选栏下拉：全部仓库标签页会独立保存所选分类，仪表盘使用自己的临时分类条件。分类数据及新增、重命名、删除能力保持不变；左侧保留收藏、项目快捷入口、位置和访达式标签。所有项目／所有 Git 仓库筛选可以命名保存为本机智能集合，完整恢复统一查询、名称/README 搜索字段和仓库标签；没有集合时侧栏不显示空区块。集合可直接拖动排序，也可从“更多”或右键菜单重命名、上移、下移和移除；移除只删除快捷入口。智能集合不保存目录绝对路径、不复制文件，也不修改 Git、项目清单或 Local Project Manager 数据。

“更多筛选…”既提供最近 24 小时/7/30/90 天和常用文件大小预设，也支持包含边界的精确起止日期、最小/最大文件大小。日期按本机日历日解释；大小可使用 B/KB/MB/GB/TB，持久化时统一为完整字节数。相对日期与精确日期、大小预设与精确大小分别互斥；反向范围、非法日期或不能换算为完整字节的输入不会关闭弹窗或污染当前标签页查询。精确日期可用于当前目录、所有项目和所有仓库，文件大小仍只用于当前目录文件，不会触发跨受管位置的递归文件扫描。

通过顶部右侧齿轮、macOS“GitFinder → 设置…”菜单、macOS `⌘,` / Windows `Ctrl+,` 或项目空状态的“打开应用设置”都会进入同一设置页。其中“记住每个目录的显示方式”开启后，每个目录会分别保存图标/列表/分栏/图库、排列依据、方向和分栏宽度；未记录目录继续使用全局默认。分栏宽度限制为 180–520 像素，可拖动列边界，聚焦边界后用方向键微调、Shift 加速、Home/End 跳到最小或最大值，双击恢复 260 像素；设置页也可调整全局默认。分栏最多展示最近 6 层路径，较深位置自动聚焦末端列；祖先列用于连续下钻，当前列继使用统一的单选、多选、拖拽、右键和文件操作模型。图库复用同一选择与文件操作模型，以大预览配合横向胶片条展示安全栅格图片、Markdown、开发文本、目录摘要和不支持格式提示；可见图片按需生成固定尺寸 PNG 缩略图，最多 4 个并发，内存缓存限制为最近 128 项，并按路径、大小和修改时间自动失效。文本最多向 DOM 放入 8,000 个字符，异步预览或缩略图切换时会拒绝过期结果，也不会生成可点击的 Markdown 外链。记录只保存在 GitFinder 本机配置中，最多保留最近 500 个，目录移动时随路径事务一起重绑定，也可在设置页集中清除；不会写入 `.gitfinder/project.json`。

目录超过 320 项时，四种视图先同步显示前 120 项，再按每帧最多 180 项补齐，其间在内容区和状态栏显示完整进度。列表超过 1,000 项时改用固定行虚拟窗口；图标视图在超过 1,000 项且条目均为高度可预测的普通文件/文件夹时，改用响应式多列虚拟窗口。两者都只在 DOM 保留视口附近项目和有限过扫描；含项目简介、Git 状态、标签等可变高度内容的图标视图继续使用渐进显示。目录数据本身不会截断；全选、Shift 范围选择、Home/End 和方向键继续使用完整排序。切换目录、视图或标签页会取消旧批次并销毁旧虚拟窗口，迟到读取不能覆盖新位置。

当前目录完成读取后，可从“排列与显示 → 性能诊断…”查看本次目录读取、筛选准备、首批 DOM、完整显示、总项目数、当前 DOM 项数和实际显示策略。指标只保存在本次会话内存，不写入本机配置、项目文件或 Git，也不会为了诊断读取额外文件内容；它们只代表当前设备和本次操作，不作为跨设备性能承诺。

空格 Quick Look 首次最多读取 1 MB 文本；若支持继续读取，底部会显示当前字节范围、起始行和“加载下一段”。后续每段最多 256 KB，界面只保留当前分段，累计读取到 8 MB 安全上限后停止。分页能力令牌随机生成、五分钟过期且只能消费一次，并绑定受管真实路径与文件版本；文件在预览期间发生变化、后续分段出现二进制内容、请求越界或重复使用令牌都会被拒绝。关闭或重新打开 Quick Look 会撤销尚未消费的令牌，不会 stage、commit 或修改源文件。

ZIP Quick Look 只读取文件尾部与最多 8 MB 的中央目录，最多解析 10,000 个条目并显示前 500 个，展示内部路径、压缩方式、压缩前后体积和加密标记；它不解压、不执行，也不读取条目正文。损坏、分卷、Zip64、目录超限或预览期间变化的归档会明确拒绝，不会退回普通二进制文本处理。

二进制 `.plist` 默认仍只显示格式说明，不会隐式启动外部程序。macOS 用户可明确点击“转换后预览”，由主进程使用绝对路径 `/usr/bin/plutil`、无 shell、限时限量地把受管真实文件转换为标准 XML stdout；结果只保存在内存中。转换前后会复核文件身份，超过 8 MB 的来源或输出、非 `.plist`、非 `bplist00`、符号链接逃逸、转换期间发生变化或无效 XML 都会拒绝。Windows/Linux 当前不显示转换按钮，继续使用默认应用打开。

常用开发文件在 Quick Look 中使用带行号的有限词法高亮，覆盖 JavaScript/TypeScript、Python、Shell、SQL、C/C++、Java/Kotlin、Go/Rust/Swift、HTML/XML、JSON/YAML/TOML 和 CSS 系列。实现不执行文件内容、不加载外部脚本或解析器；每个源码字符先进行 HTML 转义，再只包裹固定类别的样式。超过 4,096 字符的单行完全降级为普通转义文本；单行达到 192 个高亮 token 后，其余部分不再创建 token 节点，避免不受控的 DOM 膨胀。

搜索框右侧可在“当前”和“全局”之间切换；按 `⌘F` 可直接进入全局搜索。默认的“名称与路径”模式跳过 `.git`、`node_modules`、构建产物和隐藏目录，只持久化名称、路径、类型、大小和修改时间等本机文件系统元数据。仓库分类和标签不写入该索引，而是在每次查询时从 GitFinder 本机配置即时叠加；应用重启后可直接恢复索引，文件操作后按目录修改时间增量更新。

只有在全局搜索中显式切换为“文件内容”，GitFinder 才会为当前查询读取文本。内容模式至少需要 3 个字符，只检查受管根内的白名单开发文本，跳过隐藏目录、依赖/构建产物、二进制、非 UTF-8/无 BOM UTF-16、符号链接和超限文件。单文件最多读取 512 KB，单次最多 2,500 个文件与 64 MB；切换查询或点击取消会停止旧扫描。结果只返回匹配行号和最长 240 字符的已转义片段；文件内容与片段都不会写入持久化索引。搜索结果可直接预览、打开或整理；空格 Quick Look 首次读取最多 1 MB 文本，并可按需分段读取到 8 MB 安全上限，栅格图片上限为 12 MB。

仓库的“提交”按钮会打开提交前审查面板，分别列出已暂存、未暂存、未跟踪和冲突文件。普通文本修改可在 diff 中按新增/删除行勾选，先生成零写入预览，再确认暂存或取消暂存；新增、删除、重命名、冲突、二进制和截断差异继续使用整文件操作。主进程生成差异指纹和短期能力令牌，应用前重新读取 HEAD、索引与文件差异并执行 `git apply --check`；渲染层不能提交任意 patch。普通提交只包含明确暂存内容，不执行 `git add .` 或 `git add --all`。

勾选“修订最近提交”会读取当前 HEAD、已暂存范围、进行中的 Git 操作和包含 HEAD 的远程跟踪引用。amend 必须先预览、再确认；预览后 HEAD 或索引变化会拒绝旧请求，合并、rebase、cherry-pick、revert、bisect、sequencer 或索引锁期间也会拒绝。若远程跟踪引用已经包含 HEAD，最终按钮保持禁用，直到用户明确确认历史改写风险。未暂存内容不会被隐式加入 amend。

顶部“开发任务”视图会自动发现受管目录内的 Local Project Manager，读取 `portfolio/projects.csv`、`management/exports/progress-summary.json` 与项目进度投影。界面可按项目、状态、优先级和关键词筛选，查看下一步行动、验收条件、项目事实证据和关联仓库，并可直接下钻到项目目录或终端。读取连接器支持 schema `1.1`；路径重绑定与投影过期都会明确提示。GitFinder 自身不改写业务 CSV，确认后的任务变更由 Local Project Manager 自有的 `scripts/gitfinder_authority.py` 校验和写入。

任务可在“列表”“看板”和“时间线”之间切换；看板严格沿用 Local Project Manager 的原始状态，不合并或猜测任务阶段，空状态列和未知状态也会保留。显示方式会持久化，点击卡片更新右侧详情时保留看板横向位置。看板不以拖动直接改状态；右侧“推进任务”会先生成零写入预览，展示当前值、目标值、修订、校验结果和受影响文件，只有再次人工确认后才应用。应用会重新校验修订与当前状态，创建备份、追加人工活动、重建投影，并用 operation id 防止重复提交。

“时间线”只读取权威投影中的活动、证据、验收、自动化运行和运行步骤，按日期跨项目排序，并可按项目、事件类型和关键词筛选。测试证据单独标识；活动或自动化步骤已引用的证据合并在同一事件中，避免重复卡片。临时 Git 工作区状态不会进入历史，带任务归因的事件可直接返回任务详情。

任务详情的“编辑任务”仅开放标题、负责人、开始日期、目标日期、优先级和下一步行动六个白名单字段；阶段、父任务、状态和 ID 不会混入编辑。编辑后必须先逐项审查规范化差异，才能人工确认应用。权威适配器会检查日期关系、同字段待确认建议和预览修订；应用继续复用进程锁、备份、原子替换、活动审计、投影重建、失败回滚和 operation id 幂等保护。

“新建任务”会从权威投影选择项目、阶段和可选父任务；任务 ID 由主进程生成，初始状态固定为“未开始”。预览会校验 ID 是否被正式任务或待确认草案占用，并展示全部计划字段。人工确认后，Local Project Manager 同时写入任务、`__created__` 计划差异和创建活动；修订冲突或投影重建失败不会留下半写入任务。

任务详情按需读取关联仓库的本机 Git 实况，不执行 `fetch`，并在 30 秒内复用缓存。只有提交信息精确引用任务 ID，或投影证据显式声明了 commit hash，才会进入“明确关联提交”；工作区变更与其他近期提交只作为未归因上下文展示，不能据此自动认定任务完成。可从实况卡片直接打开现有仓库审查面板。

“关系白板”用于表达项目、仓库、部署、服务器和公开端点之间的事实链。项目与仓库仍引用 GitFinder 稳定身份；部署节点将环境、版本、分支、提交和声明状态保存为彼此独立的受控字段，节点副标题、搜索和部署摘要共用这些字段，不再把版本上下文塞进备注。选择服务器节点时，右侧“关联部署”从既有 `contains`、`source_of` 和 `runs_on` 事实链派生项目、仓库、部署和版本清单；“定位”只切回完整事实、清除遮挡筛选并居中当前白板中的部署节点，不连接服务器或检查实时状态。拖动只修改布局；建立关系、导入 JSON 或同步外部观测都不会执行 Git 或部署操作。“添加节点 → 连接 Coolify…”支持用户主动输入实例地址和只含 `read` 权限的团队 Access Token：令牌仅用于本次主进程读取，不写入设置或白板；读取结果先显示字段白名单化后的差异，确认后才创建备份并非破坏合并。当前代码只调用服务器、服务器资源和应用三个 GET 端点，远程仓库只有唯一匹配本机仓库身份时才连线；Coolify 分支和短提交会进入对应结构化字段。这是一份带时间戳的只读快照，不代表持续健康监控。

### 4. 构建桌面应用

```bash
# 构建并验证 ad-hoc 签名的本机开发版本
npm run pack

# 单独复核现有开发产物
npm run verify:release

# 只能在真正 Windows x64 主机上构建 NSIS 安装包和 ZIP
npm run pack:win
```

`npm run pack` 和默认的 `npm run dist` 都只生成开发包，并在 `dist/release-verification.json` 中明确记录 `eligibleForDistribution: false`。正式发布不能通过改名或手工上传该 ZIP 完成；它必须从与 `package.json` 一致的版本标签构建，使用 Developer ID Application 签名、Hardened Runtime 和安全时间戳，通过 Apple 公证、票据验证与 Gatekeeper 后，验证报告才会标记为可分发。证书和公证凭据配置见 [自动更新发布说明](docs/自动更新发布说明.md)。

Windows 构建脚本会在非 Windows 主机上直接失败，避免把 macOS 交叉打包误报为真实验证。`windows-latest` CI 会运行项目配置、Git for Windows、复制/移动/回收站验收，再检查免安装默认启动、NSIS 静默安装、安装后默认启动与卸载；启动门禁不再附加会掩盖虚拟显卡问题的 `--disable-gpu` 参数。GitFinder 的文件管理和关系白板不依赖 GPU，因此 Windows 默认使用 Electron 软件渲染，并关闭 WebGL，以提高 Parallels、VMware、VirtualBox 等虚拟显卡环境的启动兼容性；GPU、渲染进程和主进程异常会写入 `%TEMP%\git-status-monitor-startup.log`。产物附带版本、x64、SHA-256 和签名/安装验证报告；签名状态不是 `Valid` 时只上传为 `unsigned-test-build` CI 附件，明确保留 SmartScreen 风险，不进入稳定 GitHub Release。

### 三入口设计

1. **CLI** (`cli.js`) - 命令行工具，直接输出到终端
2. **Server** (`server.js`) - Web 服务器，提供 API 和静态页面
3. **Electron** (`main.js`) - 桌面应用，集成服务器和浏览器窗口

### 核心模块

- **scanGitRepos** - 扫描目录下的 Git 仓库
- **getGitStatus** - 获取单个仓库的详细状态
- **loadCache / saveCache** - 缓存管理（1小时过期）
- **quickLookController** - 管理安全预览、分页请求与能力令牌生命周期
- **fileOperationController** - 管理文件剪贴板、系统路径名复制、操作历史、撤销/重做、编辑动作路由与操作后刷新链
- **fileTransferController** - 管理复制/移动/导入审查、冲突与结构风险确认、进度轮询、取消和完成后选择恢复
- **directoryNavigationController** - 管理目录路径、受管根边界、后退/前进/上级历史、面包屑与跨平台根路径语义
- **sidebarTreeController** - 管理受管位置根、项目/Git 语义图标、展开状态、断开位置与当前目录同步
- **RepositoryRootScanner** - 只扫描可用受管根；部分断开时合并既有仓库记录且不覆盖完整持久索引
- **directorySelectionController** - 统一目录项的单选、多选、范围选择、全选、ARIA 状态和键盘焦点
- **fileActionBarController** - 根据选择、剪贴板、忙碌和历史状态统一文件操作栏及收纳菜单的启用状态
- **fileSelectionDetailController** - 统一当前文件选择摘要、语义图标和文件夹/项目快捷动作
- **repositoryDetailController** - 并行读取仓库详情、隔离迟到选择，并统一 Git 状态、分类、标签及详情区布局
- **ContentQuery** - 统一当前目录/所有受管位置、文件类型、项目身份、Git 属性/状态、仓库分类和高级条件，并迁移旧标签页筛选状态
- **contentFilterController** - 管理每个标签页的 Git 状态、项目生命周期、扩展名、修改时间与文件大小高级筛选弹窗
- **SmartCollections** - 规范化、限量并匹配本机命名筛选，拒绝把易失效的当前目录条件伪装成全局集合
- **smartCollectionsController** - 管理智能集合的保存弹窗、原子配置写入、侧栏恢复与移除交互
- **ProjectShortcuts** - 规范化本机固定/最近项目记录，以稳定 `projectId` 解析移动后的项目位置，并避免把项目快捷区重新变成分类视图
- **SemanticColors** - 管理普通目录、默认项目、Git 角标/线条及生命周期标签的预设、自定义和安全 CSS 变量
- **virtualDirectoryWindow** - 管理超大列表的固定行窗口、过扫描与键盘目标滚动

## 配置说明

### 默认扫描路径

默认扫描路径根据操作系统自动选择：

- **macOS/Linux**: `~/Projects`
- **Windows**: `%USERPROFILE%\Projects`

可通过以下方式修改：

1. **CLI**: 使用 `--path` 参数
2. **Web**: 在界面输入框中修改
3. **API**: 调用 `/api/default-path` 获取默认路径

### 自动刷新间隔

Web 界面支持自动刷新，默认间隔为 60 秒。可通过界面开关启用/禁用。

### 自动 Fetch

扫描时默认不执行 `git fetch`，以提高扫描速度。如需获取最新的远程状态，可在 API 请求中设置 `autoFetch: true`。

### 排除目录

扫描时自动跳过以下目录：

- `.git`, `.DS_Store`, `node_modules`, `vendor`
- `__pycache__`, `.venv`, `env`
- macOS 系统目录（`.DocumentRevisions-V100`, `.Spotlight-V100` 等）

## 注意事项

### ⚠️ 性能提示

- `git fetch` 操作会影响扫描速度，建议在网络较慢的环境下保持 `autoFetch: false`
- 如需获取最新远程状态，可手动点击 "Fetch" 按钮或启用 `autoFetch`
- 超过 320 项的目录会渐进显示且不丢项目；超过 1,000 项的列表及普通文件/文件夹图标网格仅保留视口附近 DOM，富项目/仓库卡片继续渐进显示；切换目录或视图会安全取消旧批次和窗口监听
- “排列与显示 → 性能诊断…”可核对本次读取、首批 DOM、完整显示和当前 DOM 数；指标仅存在会话内存，用于定位真实目录瓶颈

### ⚠️ 安全警告

- **commit 操作**只提交审查面板中已经明确暂存的内容；未暂存、未跟踪或冲突文件不会被隐式加入
- Electron 模式启用 `contextIsolation`、渲染沙箱、CSP、导航限制和 IPC 发送方校验
- Web 写操作默认关闭；Git 参数通过进程参数传递，不拼接进 shell

### ⚠️ 权限问题

- 需要对扫描路径有读取权限
- 需要对仓库目录有写入权限才能执行 commit/push/pull 操作

## 常见问题

**Q: 扫描不到仓库？**

A: 请检查：
- 路径是否正确
- 是否有读取权限
- 目录是否包含 `.git` 文件夹

**Q: 远程操作失败？**

A: 请检查：
- Git 远程仓库配置是否正确
- 是否有网络连接
- 是否有权限访问远程仓库

**Q: Electron 应用无法启动？**

A: 请确保已安装依赖：
```bash
npm install
npm run electron
```

**Q: 如何修改默认扫描路径？**

A: 在 Web 界面的输入框中修改，或使用 CLI 的 `--path` 参数。
