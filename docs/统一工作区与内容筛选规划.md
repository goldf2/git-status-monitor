# GitFinder 统一工作区与内容筛选规划

> 状态：信息架构、统一查询对象、旧标签迁移、Git 状态、首批高级条件与智能集合首版已完成。
> 日期：2026-08-28

## 背景

迁移前顶部菜单同时包含“目录、项目、全部仓库、仪表盘、开发任务”。其中“仪表盘、开发任务”确实是不同工作空间，但“项目、全部仓库”同时承担了内容类型和聚合方式，和目录页已有的内容筛选重复。

目录、项目身份与 Git 属性也不是互斥关系：项目首先是文件夹，Git 仓库是可以叠加在普通文件夹或项目文件夹上的属性。因此不应继续把三者设计成三个互斥的一级页面。

## 推荐信息架构

### 一级工作空间

- 文件浏览：日常目录和文件管理。
- 仪表盘：跨位置的统计和概览。
- 开发任务：Local Project Manager 的任务、里程碑和时间线。
- 关系白板：服务器、项目、仓库、部署实例与入口之间的关系画布。

一级菜单只切换页面结构明显不同的工作空间。

### 文件浏览中的查询条件

文件浏览使用一个漏斗形“内容筛选”菜单，按以下维度组合：

1. 范围（单选）
   - 当前目录
   - 当前项目
   - 所有受管位置
2. 基础类型（单选）
   - 全部
   - 文件夹
   - 文件
3. 身份与属性（可多选，跨组使用 AND）
   - 仅项目：`isProject === true`
   - 仅 Git 仓库：`isGitRepo === true`
4. 状态（可多选）
   - Git：已同步、未提交、未推送、需拉取
   - 项目生命周期：待整理、开发中、验证中、已部署、维护中、暂停、冻结、废弃、归档
5. 元数据与内容条件
   - 仓库分类、仓库标签
   - 名称、扩展名、修改时间、大小
   - 显式启用的文件内容搜索；继续遵守现有本机读取和限量边界

“仅项目”和“仅 Git 仓库”同时勾选时，只显示同时具备项目身份和 Git 属性的文件夹。这与四种视觉语义保持一致：普通文件夹、普通文件夹加 Git 角标、项目文件夹、项目文件夹加 Git 角标。

## 预设替代旧模式

- 旧“目录” → 文件浏览 + 当前目录 + 全部内容。
- 旧“项目” → 文件浏览 + 所有受管位置 + 文件夹 + 仅项目，并按项目聚合。
- 旧“全部仓库” → 文件浏览 + 所有受管位置 + 文件夹 + 仅 Git 仓库。

迁移已从一级工作区菜单移除“项目”和“全部仓库”，并在内容筛选中加入“当前目录”和“所有受管位置”两个明确分组。当前目录的“项目”与“Git 仓库”是可同时勾选的属性；全局项目/仓库结果仍复用文件浏览工作区。旧标签页状态兼容读取并一次性迁移到统一查询对象，旧 `projects` / `grid` 不再作为运行时工作区模式。

仓库分类和仓库标签属于 GitFinder 的仓库元数据，不是项目生命周期或项目颜色配置。仓库分类不再作为左侧固定导航区，而是位于“所有受管位置 · Git 仓库”和仪表盘的筛选栏下拉；全部仓库标签页独立持久化分类条件，仪表盘继续使用隔离的临时条件。左侧保留访达式标签入口；当前目录、项目结果、项目 + Git 交集和开发任务不会显示仓库元数据筛选。

项目分类能力不应重新形成隐性的“项目视图”。左侧可以保留“项目”导航快捷区，但它只包含“所有项目”、用户固定项目和最近项目：点击具体项目进入统一目录页，“所有项目”应用全局项目筛选。快捷偏好只保存稳定 `projectId`、最后已知名称和最近时间，不保存绝对路径，不写项目便携清单；失效的固定项目保留明确提示并允许取消固定。项目生命周期、颜色及后续业务分类都作为项目属性进入内容筛选；常用的所有项目／所有仓库组合可以命名保存为“智能集合”，没有保存集合时不显示空的侧栏区块。集合支持从收纳式菜单重命名、上移、下移和移除，也可直接拖动排序；集合自身顺序属于本机侧栏偏好。首版集合只保存全局内容查询、名称/README 搜索字段和仓库标签，不固化当前目录绝对路径，也不保存内容结果的排序或显示方式。

## 交互建议

- 工具栏显示漏斗图标与摘要，例如“内容 · 项目 · Git · 12”。
- 已启用条件在工具栏下方显示可单独移除的筛选胶囊，并提供“清除全部”。
- 视图菜单只管理图标、列表、分栏、图库及后续白板布局，不混入内容条件。
- 排序保持独立，继续提供名称、修改时间、大小、Git 状态等字段。
- 空结果明确说明是哪个条件导致，并提供一键放宽范围或清除筛选。
- 每个工作区标签页独立记住范围、筛选、排序和显示方式。

## 可验证的实施切片

### A. 补齐当前目录筛选（已完成）

- 将“全部 19”改名为“内容 19”并加漏斗图标。
- 在现有筛选中增加“仅项目”。
- 保持现有目录、Git 仓库和文件筛选兼容。
- 增加筛选结果计数、空状态和回归测试。

### B. 建立统一查询模型（首版已完成）

- 已将范围、基础类型、项目身份和 Git 属性规范化为可持久化 `contentQuery`；状态条件留待切片 D。
- 基础类型单选；项目与 Git 属性可组合，并按 AND 取交集。
- 旧 `directoryTypeFilter`、`projects` 和 `grid` 只作为会话迁移输入；标签会话格式保持 v2，内部 `contentQuery` 已升级到 v4 并立即保存修复结果。

### C. 把项目与仓库模式迁移为预设（已完成）

- 顶部不再显示“项目”和“全部仓库”；内容筛选提供“所有项目”和“所有 Git 仓库”快捷预设。
- 项目聚合只改变组织方式，不创建重复目录记录。
- 当前目录和所有位置在筛选按钮、搜索范围、面包屑、状态栏与标签提示中显式区分。
- 旧项目/仓库标签继续恢复，并迁移为文件浏览工作区内的全局内容预设。

### D. 扩展内容与状态筛选（首批完成）

- 已增加 Git 综合状态/无远程、项目生命周期、扩展名、最近修改时间、精确修改日期、分段文件大小和精确字节区间；高级条件按标签页持久化。
- 仓库分类已从左侧固定导航迁入筛选栏下拉；全部仓库分类条件进入同一标签页查询，仪表盘分类条件保持隔离。
- Git 综合状态多选为 OR，“无远程”作为独立 AND 条件；全部仓库筛选栏和更多筛选弹窗读写同一标签页查询，仪表盘临时筛选保持隔离。
- 生命周期多选为 OR，并自动限定项目；扩展名/大小自动限定文件，两组互斥。修改时间可与任一类型组合；精确起止日期均为包含边界并按本机日历日解释。
- 相对日期与精确日期二选一，大小预设与精确大小二选一。精确大小使用 B/KB/MB/GB/TB 输入并持久化为安全整数的字节边界；反向或非法范围保持弹窗打开且不修改当前查询。
- 所有位置对项目生命周期或仓库 Git 状态生效，不递归读取全部文件；普通目录不会为筛选自动读取每个仓库状态。
- 内容搜索继续要求用户显式切换，不在普通名称筛选时读取文件内容。
- 已支持把所有项目／所有 Git 仓库的当前筛选命名并固定到侧栏，点击后恢复查询、名称/README 搜索字段与仓库标签；最多 50 个，损坏记录安全丢弃，本机配置写入失败时不发布半完成状态。
- 智能集合支持“更多”按钮和右键上下文菜单，可重命名、上移、下移或仅移除快捷入口；鼠标也可直接拖动重排。顺序与名称继续使用同一原子本机配置写入，不改变已保存的筛选内容。
- 当前目录筛选、排序和显示方式暂不进入智能集合：前者避免固化易失效绝对路径，后两者继续由标签页和逐目录显示偏好负责。

### E. 项目快捷导航（已完成）

- 左侧“项目”不显示业务分类，只显示所有项目、固定项目和最近项目。
- 点击项目复用统一目录导航、标签历史和内容查询恢复流程；点击“所有项目”只应用全局项目筛选。
- 固定与最近记录只进入本机偏好，最多固定 20 个、最近 8 个；目录路径不进入该偏好。
- 项目移动后用 `projectId` 重新解析；暂时找不到的固定项目显示“不可用”，最近失效项不占侧栏。
- 应用设置可隐藏整个项目区、只隐藏最近项目、将最近数量设为 3、5、8 个，或清除最近记录；这些都是本机显示偏好，不影响全局项目筛选和项目身份。

## 首批验收标准

- 顶部工作空间不再把目录身份与 Git 属性描述成互斥页面。
- 同一文件夹在同一结果中只出现一次，并可同时展示项目身份与 Git 角标。
- 可以筛选普通文件夹、项目、Git 仓库、项目加 Git、普通文件。
- 筛选范围、条件、排序与显示方式在标签页恢复后保持一致。
- 普通筛选不读取文件内容、不执行 Git 写操作，也不修改 `.gitfinder/project.json`。
