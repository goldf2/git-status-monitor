# GitFinder 关系白板功能规划

> 状态：阶段 A 已在源码中实现；阶段 B 已完成事实详情、可配置复核周期、核验状态、白板筛选、精简节点显示、部署摘要投影、项目/仓库详情下钻和多节点布局操作；阶段 C 已完成受控 JSON 文件导入、差异预览与确认合并的首个切片。事实详情已在隔离用户目录下完成 macOS 桌面手动验证；新增周期、筛选、投影、多选和导入切片目前完成源码测试，尚待桌面视觉复核。尚未生成新的安装包，也尚未在真实 Windows x64 环境验证。

## 1. 目标

在 GitFinder 的“视图”菜单中增加“关系白板”，用 ComfyUI 式节点和拖拽连线表达本地开发对象之间的关系。首个高价值场景是：

- 某台服务器运行了哪些部署实例。
- 每个部署实例对应哪个 GitFinder 项目和 Git 仓库。
- 某个项目在开发、测试、生产环境分别部署在哪里。
- 关系是人工声明、外部导入，还是最近验证过的事实。

白板只管理可视化关系，首批不执行 SSH、部署、重启、拉取或 Git 写操作。

## 2. 关键建模决策

不直接用一条“服务器 → 项目”连线代替全部事实。底层模型保留“部署实例”：

```text
项目 ──包含──> Git 仓库 ──作为源──> 部署实例 ──运行于──> 服务器
                                      │
                                      └──暴露──> 域名/服务端点
```

这样可以分别保存环境、版本、分支、容器/应用名、域名和验证时间。界面现已提供“部署摘要”关系层级，把完整的项目→仓库→部署→服务器链派生为用户直观的项目→服务器摘要线，但不删除或改写底层信息；切回“完整事实”立即恢复原图。

### 节点类型

| 节点 | 稳定身份 | 首批信息 |
| --- | --- | --- |
| 服务器 | GitFinder 生成的 `serverId` | 名称、类型、地址提示、标签；不保存密码/密钥 |
| 部署实例 | GitFinder 生成的 `deploymentId` | 环境、应用名、版本/分支、域名、事实来源 |
| 项目 | `.gitfinder/project.json` 的 `projectId` | 名称、生命周期、项目色 |
| Git 仓库 | GitFinder 稳定 `repoId` | 本地相对身份、分支、Git 状态 |
| 端点 | GitFinder 生成的 `endpointId` | 域名/端口提示、环境；不存储访问令牌 |
| 备注组 | 白板内 ID | 视觉分组和说明，不参与事实推理 |

### 关系类型

首批固定为 `contains`、`source_of`、`runs_on`、`exposes`、`depends_on`。端口只允许符合类型约束的连线，例如 `runs_on` 只能从部署实例连到服务器。错误类型在拖拽时就拒绝，不保存“之后再修”的无效图。

## 3. 事实与布局分离

白板数据分成两层：

1. **关系事实**：节点身份、关系类型、来源、验证时间。
2. **白板布局**：节点坐标、尺寸、缩放、分组、折叠和显示筛选。

拖动节点只修改布局。拖动端口建立连线时，才通过一个可撤销操作新建关系事实。

### 当前本机文件

```text
Application Support/GitFinder/
└── relationship-boards.json
```

- 当前用单个版本化 JSON 保持实体、关系和白板布局的一次原子提交，数据结构仍明确分为 `entities`、`relationships` 与 `boards[].placements/viewport/view`，拖动和筛选不会改变事实字段。
- 使用原子写入、2 MB 文件上限、20 个白板、200 个节点和 400 条关系上限；语法或语义损坏时先备份原文件，再写入可恢复状态。
- 对项目和仓库只记录稳定 ID，不把绝对路径作为长期关系键。
- 服务器连接凭据不进入上述文件；Coolify 首个连接器使用一次会话令牌读取，响应返回后丢弃令牌。未来需要周期刷新时再单独评估系统凭据库，不把密钥混入白板事实。
- 首批不写入项目的 `.gitfinder/project.json`，不把本机白板坐标变成便携项目事实。

每个节点和每条关系事实可保存 `source` (`manual`/`imported`/`observed`)、`verifiedAt`、可选 `evidenceSummary` 和可选 `reviewIntervalDays`。复核周期限定为 1–3650 个整数天，留空使用 30 天默认值；超过周期的事实显示“待复核”，不冒充当前运行状态。

## 4. 交互与界面

- **已实现入口**：顶部“视图”下拉菜单和系统“显示”菜单均提供“关系白板”，没有新增一级平铺工具按钮。
- **已实现画布**：中央网格支持节点拖动、空白处平移、滚轮/触控板缩放和“适合内容”，视口随白板保存。
- **已实现资源抽屉**：可搜索当前 GitFinder 项目和仓库；点击或原生拖拽加入画布。抽屉显示的绝对路径只是当次解析信息，不写入白板文件。
- **已实现节点**：项目、Git 仓库、服务器、部署、端点和分组六类节点；资源节点保存稳定 `projectId`/仓库注册 ID，失效引用保留并明确标记。节点以灰、绿、琥珀状态点区分待验证、已验证和待复核。
- **已实现连线**：输出端口到兼容目标 1:1 跟随指针，合法目标高亮；固定类型约束、拒绝重复关系，并用箭头表达方向。反向排列自动选择相邻端口，避免连线绕到画布外侧。
- **已实现详情与核验**：选择节点或关系后从右侧渐进显示非模态检查器；可编辑手工节点名称/环境/状态/备注，以及固定来源、验证时间、复核周期和证据摘要。来源限定为人工声明、外部导入、只读观测和 GitFinder 注册表；验证时间统一保存为带时区 ISO 时间。无验证时间显示“待验证”；每条事实可覆盖默认 30 天复核周期，周期会一致参与节点、关系、筛选和部署摘要状态，但不会触发连接或执行操作。
- **已实现筛选与节点显示**：工具栏保留单一“筛选”入口，展开锚定式弹层后可按关键字、节点类型、环境和核验状态组合筛选，也可切换完整/精简节点显示。直接匹配节点会保留一跳相连节点作为弱化上下文，避免筛选后只剩无法解释的孤立节点。每块白板独立保存筛选与显示偏好；清除筛选不会改变节点显示模式。
- **已实现部署摘要**：关系层级可在“完整事实”和“部署摘要”间切换。只有完整的项目→仓库→部署→服务器事实链才会被折叠；同一项目到同一服务器的多个部署聚合计数，并继承链路中最弱的核验状态。部署还连接端点、依赖等额外事实时保持完整链，避免折叠后留下孤立对象；筛选直接命中仓库或部署时也保留该局部事实。摘要边是不可编辑的派生显示，不进入 `entities` 或 `relationships`。
- **已实现跨工作区下钻**：所有项目聚合卡片、目录详情中的项目/Git 文件夹，以及仓库详情均可“在关系白板中显示”。入口先解析 `projectId` 或仓库注册 ID，再切换白板、加入或选中当前节点并清除遮挡它的筛选；不会用可变绝对路径建立关系身份，也不会自动创建事实连线。
- **已实现多选、撤销与键盘**：Cmd/Ctrl 点击切换多选，Shift 在空白画布拖出选择框；所选节点可成组拖动、方向键移动或一次移出当前白板，保持相对布局并只生成一个撤销快照。节点可聚焦，键盘可选择连接起点和目标；降低动效设置下取消过渡。多选检查器只提供布局操作说明，事实字段仍必须逐个编辑，避免混淆来源和核验状态。
- **已实现 JSON 文件导入**：从“添加节点”下拉菜单使用系统文件选择器选取完整 GitFinder 关系白板 JSON。文件只在主进程读取，限制为普通文件和 2 MB，严格验证模型字段、关系方向与敏感内容；渲染层不接收文件路径。预览以五分钟一次性令牌绑定源文件 SHA-256 和当前白板修订，显示新增/更新节点、关系及布局差异；确认前零写入。确认后只合并新增或更新内容，不删除现有事实，先生成导入前备份再原子保存；预览后源文件或本机白板发生变化、令牌过期或篡改时拒绝应用。导入事实标记为 `imported`，不会因一次读取就显示为实时健康状态。
- **已实现 Coolify 只读连接器首个切片**：用户主动填写实例根地址和只含 `read` 权限的团队 Access Token。主进程只调用 `GET /api/v1/servers`、`GET /api/v1/servers/{uuid}/resources` 和 `GET /api/v1/applications`，每台服务器资源请求最多四路并发；只保留 UUID、名称、类型、状态、仓库标识、分支/提交和去除查询参数的公开域名，丢弃原始响应和其他字段。令牌不进入预览记录、设置或白板文件。读取完成后生成带观测时间和一天复核周期的服务器、部署、端点、`runs_on`/`exposes` 关系；远程仓库只有唯一匹配本机 GitFinder 稳定仓库 ID 时才生成 `source_of`，未匹配项只在预览中提示。确认前零写入，确认后复用五分钟预览令牌、白板修订校验、导入前备份、非破坏合并和幂等应用。
- **尚未实现**：保存实例但不保存令牌的连接历史、周期刷新、其他平台连接器，以及真实 Coolify 实例的用户授权验收。

### 当前技术结构

当前渲染层保持原生 JavaScript，采用 **HTML 节点 + 同一变换层内的 SVG 连线**，没有为画布引入 React/React Flow：

- `src/shared/relationshipGraphModel.js`：字段白名单、敏感键拒绝、节点/关系约束、序列化和容量上限。
- `src/renderer/scripts/relationshipBoardController.js`：资源解析、HTML/SVG 渲染、缩放平移、拖动连线、键盘等价操作和撤销/重做。
- `src/main/services/relationshipBoardService.js`：普通文件/符号链接边界、原子写入、损坏备份和恢复。
- `src/main/services/relationshipBoardImportService.js`：JSON 普通文件边界、敏感内容拒绝、非破坏合并规划、差异预览令牌、源文件/白板修订复核和导入前备份。
- `src/main/services/coolifyReadOnlyConnectorService.js`：HTTPS/localhost 地址约束、会话令牌、固定 GET 端点、响应大小/并发上限、字段白名单、本机仓库稳定身份匹配和观测事实转换。
- `src/main/ipc/relationshipBoards.js` + `preload.js`：受信 IPC 和最小化渲染进程桥接面。
- `scripts/verify-relationship-user-data.js`：在真实 Electron 进程中验证服务即使在 `ready` 前被导入，也只会在 Electron `userData` 指定目录读写，不回退污染用户主目录。

首批以 200 节点/400 连线为性能目标。超过后先提供分白板、筛选和折叠，不急于上 Canvas/WebGL。
