# Git Status Monitor 自动更新发布说明

当前应用版本统一来自 `package.json`，界面底部会显示版本号。打包应用启动约 10 秒后自动检查更新，也可以点击底部的版本号或“检查更新”按钮手动检查。更新下载完成后，底部按钮会显示“重启安装”，点击后退出并安装新版本。

## 更新源

自动更新使用 GitHub Releases：

```text
https://github.com/goldf2/git-status-monitor/releases
```

构建脚本会在应用中写入 `app-update.yml`，并在 `dist/` 生成更新所需的 ZIP 和 `latest-mac.yml`。

## 发布新版本

1. 修改 `package.json` 和 `package-lock.json` 顶部的版本号，两个文件必须一致。
2. 按语义化版本选择版本号：
   - 修复错误：`1.1.0` → `1.1.1`
   - 向后兼容的新功能：`1.1.0` → `1.2.0`
   - 不兼容的大改：`1.1.0` → `2.0.0`
3. 提交源码并创建与版本完全一致的标签，例如 `v1.1.0`：

```bash
git tag v1.1.0
git push origin main
git push origin v1.1.0
```

4. GitHub Actions 会自动执行 `.github/workflows/release.yml`，在 macOS runner 上运行 `npm ci` 和 `npm run dist`，并创建/更新对应 Release。
5. workflow 会自动上传以下两个文件：

```text
dist/Git Status Monitor-1.1.0-arm64-mac.zip
dist/latest-mac.yml
```

6. Release 发布后，旧版本应用随后即可检测、下载并提示重启安装。

也可以在 GitHub Actions 页面手动运行 `Release` workflow，用于重新生成当前分支的发布附件。

## 发布前检查

```bash
node -p "require('./package.json').version"
plutil -p "dist/Git Status Monitor-darwin-arm64/Git Status Monitor.app/Contents/Info.plist"
cat "dist/Git Status Monitor-darwin-arm64/Git Status Monitor.app/Contents/Resources/app-update.yml"
cat dist/latest-mac.yml
```

确认：

- `package.json`、应用 `Info.plist`、Git 标签和 Release 版本一致。
- ZIP 文件名与 `latest-mac.yml` 中的 `url`、`path` 一致。
- `latest-mac.yml` 的 SHA-512 是 Base64 字符串。
- Release 同时包含 ZIP 和 `latest-mac.yml`，并且不是草稿状态。

## macOS 签名说明

自动下载和替换应用涉及 macOS 安全校验。正式分发时应使用 Apple Developer ID 对应用签名并完成公证；未签名的本地测试包虽然可以手动打开，但自动安装可能被 macOS 拦截。因此，在完成证书配置前，应把“手动下载 Release 并替换应用”作为备用更新方式。
