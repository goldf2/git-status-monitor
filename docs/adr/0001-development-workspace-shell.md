# ADR 0001：以 GitFinder 作为开发工作台外壳

- 状态：已接受
- 日期：2026-08-26

## 背景

GitFinder 已同时包含目录浏览、Git 状态、终端、Markdown 和项目进度入口，但当前仍以“仓库列表”为中心。用户希望最终不再依赖 Finder 管理开发任务。与此同时，`/Volumes/project/开发中/工具/local-project-manager` 已经建立项目、任务、里程碑、验收和证据的 CSV 事实源及功能牌协议。

若在 GitFinder 内重新建立另一套任务数据库，会产生状态漂移；若只保留两个独立应用，又无法实现一个入口完成开发工作的目标。

## 决策

GitFinder 作为统一桌面工作台和交互外壳：负责文件、仓库、Git、终端、文档、搜索和安全操作。Local Project Manager 作为结构化项目管理引擎，通过本地连接器或内嵌视图向 GitFinder 提供任务、进度、里程碑与证据投影。

用户从 GitFinder 进入和操作任务，但一次任务状态只写入一个项目事实源。未来若将项目管理引擎合并进 GitFinder，必须先定义数据迁移、兼容期和回滚方案，不能直接复制数据。

## 边界

GitFinder 拥有：

- 受管根目录与内容索引；
- 稳定仓库注册表、分类和标签；
- Git 状态与显式 Git 操作；
- 终端、文档和文件管理交互；
- 文件操作历史、撤销信息和桌面偏好。

项目管理引擎拥有：

- 项目、要求、任务、里程碑和验收条件；
- 活动、证据关联和人工确认状态；
- 进度计算口径和跨项目只读摘要。

## 结果

- 用户获得一个日常入口，同时避免两套任务事实互相覆盖。
- 第一阶段必须先解决稳定身份、路径漂移、配置恢复、安全边界和测试，否则文件操作与任务关联不具备可信基础。
- Finder 替代能力按可恢复文件操作逐步开放，不把“能够调用任意 shell”当作文件管理实现。
- Local Project Manager 的连接器路径必须随 GitFinder 生命周期目录变化而更新。
