# ADR 0007：本地项目身份与 Git 仓库属性分离

- 状态：已接受
- 日期：2026-08-27

## 背景

GitFinder 过去以 Git 仓库作为主要展示对象，容易把“带 `.git` 的目录”误解为“项目”。实际开发工作中，一个项目可以没有 Git、只有一个仓库，或聚合多个仓库；公开克隆的参考仓库也不应自动启用任务和生命周期。

## 决策

1. 普通文件夹或项目是目录的语义身份；Git 是可叠加属性，不改变目录身份。
2. 只有用户显式选择“设为项目”才创建 `.gitfinder/project.json`。该操作不执行 `git init`、stage、commit 或 push。
3. 清单使用独立 `projectId`，记录名称、简介、项目颜色、生命周期和仓库排除路径。排除路径必须为项目内部、用 `/` 表示的相对路径，不存储任何平台绝对路径。
4. 项目自动发现内部零个、一个或多个 Git 仓库。内部目录存在自己的项目清单时，它成为独立子项目并截断父项目扫描。
5. 主目录视图展示四种状态：普通文件夹、普通文件夹+Git 角标、彩色项目文件夹、彩色项目文件夹+Git 角标。生命周期使用独立标签，不复用颜色。
6. “项目”视图按项目聚合；“全部仓库”视图按 Git 属性筛选。同一目录不因为同时具有两种属性而在同一视图重复出现。
7. `.gitfinder/project.json` 只是 GitFinder 的本地语义、外观与仓库聚合元数据。任务、里程碑、进度与验收仍由 Local Project Manager 的权威事实源负责。

## 结果

- 仓库不再自动获得项目管理语义。
- 项目颜色、生命周期和 Git 状态可同时表达而不互相覆盖。
- 清单可随项目目录在 macOS 与 Windows 之间携带；本机工具偏好不进入清单。
