# ADR 0003：文件内容搜索使用显式、有界且不落盘的本机扫描

- 状态：已接受
- 日期：2026-08-27

## 背景

GitFinder 的全局搜索已使用持久化增量索引查找名称、路径、类型和仓库元数据。完整替代 Finder 的开发工作流还需要按正文定位代码、文档和配置，但将所有文件正文长期写入 GitFinder 用户目录会放大隐私、容量、失效和损坏恢复风险。

## 决策

1. 默认搜索仍只查元数据，不读取文件内容。用户必须在全局搜索中显式切换“文件内容”模式。
2. 内容搜索复用现有元数据索引作为候选清单，仅在当前查询中读取文件，不建立、更新或持久化正文索引。
3. 候选只包含受管根中的明确文本扩展名和常见无扩展名开发文件；隐藏目录、依赖、Git 元数据和构建产物沿用元数据索引的排除规则。
4. 查询至少 3 个字符；单文件最多 512 KB，单次最多 2,500 个文件和 64 MB。达到上限必须在界面明确提示，不默认扩大。
5. 每个候选在读取前重新校验受管根、真实路径和普通文件类型；支持的系统使用 `O_NOFOLLOW` 拒绝打开时的符号链接替换。
6. 二进制、非 UTF-8 或无 BOM 的 UTF-16 文本跳过；带 BOM 的 UTF-16LE/BE 可搜索。
7. 新查询、离开全局搜索或点击取消必须终止旧扫描。每个请求独立持有进度状态，旧请求不得覆盖新请求。
8. 返回值只包含文件元数据、匹配行号和最长 240 字符的片段。渲染层必须转义片段；片段不写入配置、标签页或磁盘索引。

## 结果

- 开发文档和代码可在 GitFinder 内按正文定位，不再必须转到 Finder 或终端做常规搜索。
- 内容搜索速度受磁盘和当次扫描上限约束，不会在后台持续读取或保留正文。
- 若未来需要完整正文索引、额外编码或更大容量，必须用新 ADR 明确数据保留、排除、加密、失效、迁移和删除方案，不得直接扩展当前索引格式。
