# ADR 0002：任务写回只能通过 Local Project Manager 权威合同

- 状态：已接受
- 日期：2026-08-26

## 背景

GitFinder 已能读取 Local Project Manager schema 1.1 的跨项目任务投影，并在桌面中提供列表、状态看板、验收证据和 Git 实况。下一步若让 GitFinder 直接修改各项目 `management/tasks.csv`，将出现第二套校验、备份、审计和投影重建逻辑，破坏单一事实源边界。

当前 Local Project Manager 的本机服务已经为自身项目提供带 revision 校验、当前状态校验、待确认建议冲突保护、备份和原子替换的状态更新端点；但该端点不支持所有注册项目，也没有独立的无副作用差异预览合同。因此它还不能作为 GitFinder 的通用写回能力。

## 决策

GitFinder 不直接写 Local Project Manager 的业务 CSV。任务状态、计划和里程碑变更必须由 Local Project Manager 所有的权威适配器执行，并满足：

1. 预览与应用分离；预览不得修改 CSV、备份或投影。
2. 请求明确包含项目 ID、任务 ID、当前值、目标值和投影修订号。
3. 预览返回结构化字段差异、影响文件、校验结果和一次性操作标识。
4. GitFinder 展示差异并取得人工确认后，才能应用同一操作标识。
5. 应用端重新校验修订号和当前值，使用原子替换，创建备份、活动记录并重建投影。
6. 重复应用同一操作标识必须幂等；冲突返回可重读的明确结果。
7. 适配器仅作为本机子进程运行，不开放网络监听；项目真实路径必须属于 GitFinder 和 Local Project Manager 共同认可的受管根。

## 当前产品行为

GitFinder v1.13.0 已实现该合同。Local Project Manager 自有的 `scripts/gitfinder_authority.py` 为注册项目提供任务创建、任务状态/字段和里程碑字段变更的零写入预览与受控应用。任务字段编辑只允许标题、负责人、开始日期、目标日期、优先级和下一步行动；里程碑编辑只允许阶段、名称、目标日期、状态和验收摘要，里程碑 ID 不可修改。里程碑应用逐字段记录 `plan_changes.csv`，并把状态完成保留为明确的人工决定。所有应用均包含进程锁、修订/当前值复核、字段白名单、备份、原子替换、活动审计、投影重建、失败回滚和 operation id 幂等保护。GitFinder 主进程只从受管投影解析对象，不接受渲染层传入路径；界面逐项展示差异并要求再次人工确认。看板仍不以拖动直接改状态；活动、证据、验收与自动化时间线保持只读。

## 结果

- 用户最终仍可在 GitFinder 一个入口推进任务。
- 校验、备份、审计和投影重建只在项目管理引擎实现一次。
- GitFinder 离线或适配器不可用时自然降级为只读，不缓存待写任务状态。
- 该决策若要改变，必须先提供数据迁移、兼容期和回滚 ADR。
