# ADR 0005：行级 Git 与 amend 使用主进程能力令牌

- 状态：已接受
- 日期：2026-08-27

## 背景

GitFinder 的提交面板原本只支持整文件 `git add` / `git restore --staged` 和普通提交。行级暂存若直接接受渲染层上传的 patch，会把主进程的受管路径校验绕成“任意补丁执行”接口；amend 若只增加一个按钮，则可能在用户没有看清索引范围、HEAD 已发布或 Git 正处于合并/rebase 时改写历史。

## 决策

1. 只有主进程可以读取权威 diff、解析 hunk 并构造选择补丁。渲染层只接收稳定的变更行身份，并回传所选身份、文件路径、层级和主进程生成的 diff 指纹；IPC 不接受原始 patch。
2. 首版行级操作只支持受管仓库中的普通 tracked 文本修改。新增、删除、重命名、复制、类型变化、未跟踪、冲突、二进制、合并差异、截断差异和超过 2,000 个变更行的文件继续使用整文件操作。
3. 未选择的新增行从补丁移除，未选择的删除行转为上下文；主进程重新计算 hunk 计数和后续新文件起始行。暂存使用正向 `git apply --cached`，取消暂存使用同一可信补丁的 `--reverse`。
4. 预览阶段执行 `git apply --cached --check --recount --unidiff-zero`，确认前绝对零写入。通过后生成两分钟有效、仓库绑定的随机预览 ID 与能力令牌，只保存于当前主进程内存。
5. 应用阶段重新读取同一 diff，校验指纹、行身份、构造后补丁哈希和能力令牌，再次执行 `--check` 后才写入索引。重复提交同一成功令牌返回幂等结果，不重复应用。
6. amend 上下文包含当前 HEAD、父提交、提交信息、显式暂存文件、冲突、审查上限、进行中的 merge/cherry-pick/revert/rebase/bisect/sequencer、索引锁，以及包含 HEAD 的远程跟踪引用。
7. amend 预览绑定 HEAD、完整索引条目、Git 操作状态和远程跟踪引用。应用前重新计算指纹；任何变化都要求重新预览。没有 HEAD、冲突、超限或危险 Git 状态时拒绝。
8. 若远程跟踪引用包含当前 HEAD，最终 amend 按钮保持禁用，直到用户明确确认历史改写风险。GitFinder 不自动执行强制推送，也不隐式暂存工作区内容。

## 结果

- 行级审查在保持主进程安全边界的前提下完成，不把 Git patch 解释权交给受攻击面更大的渲染页。
- 文件或索引在用户审查期间变化时，旧预览不会落地到新状态。
- amend 从单击历史改写变为“读取上下文 → 零写入预览 → 风险确认 → 重校验应用”的显式流程。
- 首版保守排除复杂 diff；这些文件仍可用已经验证的整文件操作，不会被静默降级为未经审查的行级写入。
