# GitFinder v1.25.0 验收记录

日期：2026-08-27

## 本次范围

- 将 macOS 构建明确拆成 `development` 与 `official` 两种模式；默认开发包继续使用 ad-hoc 签名，但验证报告固定标记为不可正式分发。
- 新增可执行的源码门禁，校验包与锁文件版本、稳定 Bundle ID、产品名、三平台图标格式和固定更新源；正式模式还要求干净工作区、版本标签与当前提交一致。
- 把 `resources/app-update.yml` 作为 Packager 额外资源，在签名和公证前进入 App Bundle，不再签名后改写资源。
- 正式模式要求 Developer ID Application 身份、Hardened Runtime 和 Keychain 公证 profile；签名发生任何错误都不能继续。
- 新增产物门禁，校验 App/asar 版本、Bundle ID、arm64 主程序、图标哈希、ZIP 完整性与布局，以及 `latest-mac.yml` 的版本、文件名、大小和 SHA-512。
- 正式产物额外要求 Developer ID Authority、正确 TeamIdentifier、安全时间戳、禁止调试 entitlement、严格 codesign、Gatekeeper 和 Apple 公证票据全部通过。
- GitHub Actions 只从版本标签执行发布作业；证书与公证凭据从 Secrets 导入临时 Keychain，只有 `eligibleForDistribution: true` 才上传附件，并在结束后删除临时 Keychain。
- Release 附件增加 `release-verification.json`，使版本、提交、哈希、签名和公证资格可独立审计。
- 删除可绕过门禁直接上传的 `npm run publish` 和 `dist:builder` 入口，正式发布只保留版本标签 workflow。
