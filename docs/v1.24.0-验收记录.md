# GitFinder v1.24.0 验收记录

日期：2026-08-27

## 本次范围

- 在文本差异视图中显示可选择的变更行、旧/新行号和增删样式，支持按行预览暂存与取消暂存。
- 把部分暂存实现为主进程生成的 Git patch：渲染层只提交稳定行标识，不上传或执行原始 patch。
- 对部分暂存增加仓库绑定、短时有效、单次能力令牌；应用前重新读取差异并校验指纹、patch 哈希和 `git apply --check`。
- 增加 amend 上下文、预览和最终执行三段流程；默认只提交索引中已经暂存的内容，不隐式暂存工作区修改。
- amend 执行前重新校验 HEAD、索引、仓库操作状态和远端跟踪引用；已发布 HEAD 必须额外勾选确认。
- 对冲突、二进制、截断、未跟踪、新增、删除、重命名、复制、类型变化和超过 2000 个变更行的文件保留整文件操作，并显示原因。
- 纳入新的 GitFinder App 图标资产，macOS 构建内图标与源图标一致。

## 已知边界

- 当前 macOS 包只有 ad-hoc 签名，`TeamIdentifier` 未设置，尚未进行 Developer ID 正式签名和 Apple 公证；严格 codesign 校验通过，但 Gatekeeper `spctl` 评估会拒绝该包。
- Windows 共用代码和 `public/icon.ico` 已进入项目，但本轮没有 Windows 实机运行、安装和签名验收。
- 按行操作仅支持普通、已跟踪、未发生冲突且未截断的文本修改；其他状态继续使用整文件操作，避免不完整 patch 或索引损坏。
- amend 是高风险历史改写操作；当前通过预览、状态指纹和已发布确认降低误操作风险，但不会自动替用户执行强制推送。
- 本轮没有提交或推送仓库改动。
